# Quilter-to-Allegro (qltr2alg) Import Scripts

This directory contains scripts for importing PCB design modifications from Quilter back into Cadence Allegro PCB Editor. The import process reads CSV files containing design changes generated by Quilter and applies them to the active Allegro design with full transaction support.

The import script provides comprehensive support for various PCB modification operations including component movement, rotation, net creation, via placement, routing changes and polygon pours.

### NOTE: Layer stack modifications are not imported yet. For polygon pours only boundary shape is imported.

## Files Description

### `Quilter_Importer.il`
**Type**: SKILL script for Allegro PCB Editor
**Purpose**: Comprehensive design modification importer with transaction support and design integrity checking

**Key Features**:
- **Automatic CSV Format Detection**: Intelligently detects and parses CSV input files
- **Transaction Support**: All modifications are applied atomically - either all succeed or all are rolled back
- **Design Integrity Checking**: Validates design state and coordinate bounds before applying changes
- **Progress Reporting**: Real-time progress updates with error tracking during import
- **Comprehensive Operation Support**: Handles multiple types of PCB modifications
- **Robust Error Handling**: Detailed logging and graceful error recovery

**Supported Operations**:
- `CREATE_NET`: Create new electrical nets
- `CREATE_VIA`: Place vias with specified padstacks and net connectivity
- `CREATE_LINE`: Create routing segments with width and layer specifications
- `CREATE_COMPONENT`: Place new components with specified footprints and positions
- `MOVE_COMPONENT`: Move components by delta coordinates with optional mirroring
- `MOVE_COMPONENT_TO`: Move components to absolute positions
- `ROTATE_COMPONENT`: Rotate components with optional origin point and mirroring
- `TRANSFORM_COMPONENT`: Apply combined transformations (move, rotate, mirror)
- `CREATE_PADSTACK`: Create custom padstack definitions
- `CREATE_POUR`: Create filled polygon shapes for power/ground planes

## Prerequisites

### Required Software
- **Cadence Allegro PCB Editor** (any recent version with SKILL support)
- **Active PCB Design**: A `.brd` file must be loaded in Allegro before importing

### CSV File Format Requirements

The CSV input file must follow this structure:

**Header Row**: Contains column names (case-sensitive)
**Data Rows**: Each row represents one modification operation

**Required Columns**:
- `operation` or `type`: Specifies the operation type (e.g., "MOVE_COMPONENT", "CREATE_VIA")

**Operation-Specific Columns**:
- **Component Operations**: `component`, `position`, `delta`, `angle`, `mirror`, `origin`
- **Net/Routing Operations**: `net`, `layer`, `start`, `end`, `width`
- **Via Operations**: `padstack`, `position`, `net`
- **Creation Operations**: `refdes`, `symbol`, `rotation`

**Coordinate Format**: Use colon-separated values (e.g., "100.5:200.0" for x:y coordinates)

## Installation

### Loading the SKILL Script
1. Start Allegro PCB Editor with your target design loaded
2. Load the SKILL script using following steps:

   In Allegro Command Line window:
   ```
   Command> set telskill
   ```

   This will open 2nd (large) SKILL terminal window
   ```
   SKILL> load("path/to/Quilter_Exporter.il")
   ```
   Observe the forward slashes used in path - alternatevly use \\ (double back slash) as path sepearator

3. Verify successful loading by checking for the message:
   ```
   === Quilter Design Update Importer Loaded ===
   Available commands:
     Quilter:importDesignUpdates filename_without_brackets - Import design modifications from file
   ```

## Usage

### Basic Import Workflow

1. **Ensure Design is Loaded**: Open your target PCB design (`.brd` file) in Allegro

2. **Prepare CSV File**: Ensure your CSV file contains properly formatted modification commands

3. **Import Modifications**:
   Example:
   ```
   Command> Quilter:importDesignUpdates "C:\path\to\modifications.csv"
   ```

### Example CSV File

```csv
operation,component,delta,mirror
MOVE_COMPONENT,U1,10.0:5.0,false
ROTATE_COMPONENT,U2,90.0,false
CREATE_VIA,VIA1,100.0:200.0,NET1
CREATE_LINE,NET1,0.0:0.0,100.0:0.0,0.2,TOP
```

### Advanced Usage with Design Validation

```
Command> Quilter:importDesignUpdates "modifications.csv" expectedTimestamp
```

The optional `expectedTimestamp` parameter enables design state validation to ensure the PCB hasn't been modified since the export that generated the CSV file.

## Import Process Details

### Transaction Support
- **Atomic Operations**: All modifications are grouped into a single database transaction
- **Rollback on Error**: If any operation fails, all changes are automatically undone
- **Design Integrity**: Original design is preserved if import encounters errors

### Progress Reporting
- **Real-time Updates**: Progress meter shows current processing status
- **Detailed Logging**: Console output provides detailed information about each operation
- **Error Tracking**: Failed operations are logged with specific error messages

### Design Units Handling
- **Automatic Conversion**: Design units are temporarily converted to microns during import
- **Restoration**: Original design units are restored after import completion
- **Coordinate Accuracy**: Ensures precise coordinate handling regardless of original units


## Troubleshooting

### Common Issues

**Error: "No design currently open"**

**Error: "Transaction failed"**
- **Cause**: One or more operations in the CSV file failed to execute
- **Solution**: Check console output for specific error messages. Common causes:
  - Component names don't exist in design
  - Invalid padstack names
  - Coordinates outside design bounds
  - Invalid net names



**Error: "Design timestamp mismatch"**
- **Cause**: The PCB design has been modified since the CSV was generated
- **Solution**: Either export a fresh CSV from Quilter or proceed without timestamp validation

**Error: "Failed to create [object]"**
- **Cause**: Invalid parameters for the specific operation
- **Solution**:
  - Verify coordinate format uses colons (e.g., "100.0:200.0")
  - Check that referenced objects (nets, padstacks, components) exist
  - Ensure numeric values are properly formatted

**Error: "File not found"**
- **Cause**: CSV file path is incorrect or file doesn't exist
- **Solution**: Verify the full path to your CSV file and ensure it exists

### Validation and Testing

**Test with Small CSV Files**: Start with a few operations to verify the import process works correctly

**Check Console Output**: Monitor the Allegro command window for detailed progress and error information

**Use Undo**: If import completes but results look incorrect, use Allegro's undo functionality to revert changes

**Backup Designs**: Always work with backup copies of important designs

## Advanced Features

### Design Bounds Validation
The importer automatically validates that coordinates fall within reasonable design bounds (±50,000 units) and warns about potentially problematic coordinates.

### Type Conversion
The CSV parser automatically handles type conversion:
- **Strings**: Component names, net names, layer names
- **Floats**: Coordinates, angles, dimensions
- **Booleans**: Mirror flags (accepts "true", "TRUE", "t", "1")
- **Coordinates**: Colon-separated coordinate pairs

### Performance Optimization
- **Database Cloaking**: Operations are performed within `axlDBCloak` for optimal performance
- **Batch Processing**: Multiple operations are processed efficiently in a single transaction
- **Progress Updates**: Processing status is updated every 50 operations to balance performance and feedback

## Command Reference

### Main Command
```
Quilter:importDesignUpdates filename [expectedTimestamp]
```

**Parameters**:
- `filename`: Path to CSV file containing modifications (required)
- `expectedTimestamp`: Optional timestamp for design validation

**Returns**:
- `t` if import succeeds
- `nil` if import fails

### CSV Operation Types

| Operation | Purpose | Required Fields | Optional Fields |
|-----------|---------|-----------------|-----------------|
| `CREATE_NET` | Create electrical net | `name` | |
| `CREATE_VIA` | Place via | `padstack`, `position`, `net` | |
| `CREATE_LINE` | Create trace segment | `start`, `end`, `width`, `layer`, `net` | |
| `CREATE_COMPONENT` | Place component | `refdes`, `symbol`, `position` | `rotation`, `mirror` |
| `MOVE_COMPONENT` | Move by delta | `component`, `delta` | `mirror` |
| `MOVE_COMPONENT_TO` | Move to position | `component`, `position` | `mirror` |
| `ROTATE_COMPONENT` | Rotate component | `component`, `angle` | `origin`, `mirror` |
| `TRANSFORM_COMPONENT` | Combined transform | `component` | `delta`, `angle`, `mirror`, `origin` |
| `CREATE_PADSTACK` | Create padstack | `padstack` | `width`, `layer`, `position`, `net` |
| `CREATE_POUR` | Create filled shape | `layer`, `position` | `net` |

## Notes

- **Net Connectivity**: Operations that specify nets will automatically connect objects to those nets
- **Layer Names**: Layer names must match Allegro design
- **Component Names**: Use exact component reference designators (e.g., "U1", "R15", "C23")
- **Transaction Safety**: Failed imports leave the original design unchanged
- **Performance**: SKILL script exectiom can take long time - progress updates bar is shown during processing
